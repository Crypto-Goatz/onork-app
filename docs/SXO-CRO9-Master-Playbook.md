## TL;DR — What "ships SXO+CRO9" means

Every page in the RocketOpp family ships with:

1. **BLUF intro** (Bottom Line Up Front, 1–2 sentences, answer first)
2. **Living DOM marker** (`<meta name="cro9:living" content="1">`) so the
   mutation engine and rank tracker know the page is variant-eligible
3. **Comparison table** within the first viewport ("table trap")
4. **FAQ schema** (5–7 voice-search-optimized Q&A pairs, JSON-LD)
5. **HowTo schema** when the page describes a process
6. **Internal-link cluster** (3–5 contextual cross-family links)
7. **CRO9 embed** (15KB, async, captures 147 behavioral metrics)
8. **UCP Live Strip** (live signal of org activity — visitors, last action)
9. **`/llms.txt`** and `robots.txt` AI bot rules at site root

Score is measured by `/api/sxo-score` (0–100). Target: **all family pages ≥ 95**.

## The 8 SXO Content Patterns

Every page should hit at least 6/8. Family service pages and money pages must
hit 8/8.

### 1. BLUF (Bottom Line Up Front)

Lead with the answer. One or two sentences. The hero subheadline is the BLUF.

```tsx
<h1>SXO Service — Rank, Convert, Repeat</h1>
<p className="bluf">
  We rebuild your highest-traffic pages into Living DOM units that mutate
  toward conversions. Average lift in 30 days: +47% qualified leads.
</p>
```

### 2. Living DOM marker

Required meta tag so CRO9 + rank tracker know this page is variant-eligible:

```tsx
export const metadata = {
  other: {
    "cro9:living": "1",
    "cro9:variant-pool": "service-page-v3",
  },
};
```

### 3. Table Trap

A comparison table in the first viewport. Must compare us against ≥2 named
alternatives. Visitors who scan see value in 2 seconds.

### 4. Voice-search FAQ (FAQPage schema)

5–7 Q&A pairs, written in natural conversational form ("How much does
SXO cost?" not "SXO Pricing"). Emit `FAQPage` JSON-LD.

### 5. HowTo schema

If the page describes a process (onboarding, audit, install), emit `HowTo`
JSON-LD with numbered steps and `totalTime`.

### 6. Internal-link cluster

3–5 contextual links to other family pages. Anchor text is descriptive, not
"click here." Builds the topical mesh that GEO loves.

### 7. `/llms.txt`

Site root file telling AI agents what to cite, what to skip, and where the
canonical sources are. Mirrors `robots.txt` but for LLMs.

### 8. UCP Live Strip

Universal Conversion Proof — a thin live signal at the top showing real
activity ("3 audits running now · last lead 12s ago"). Renders from
`/api/ucp/live`. Drives FOMO without dark patterns.

## Living DOM Architecture

Pages aren't static. They're variant-pooled and the winning variant gets
served via Multi-Armed Bandit (MAB) allocation.

```
visitor lands
  → CRO9 embed boots (15KB, async, 0 layout shift)
  → fetches /api/cro9/variant?pool=service-page-v3&visitor=<hash>
  → MAB returns variant id (epsilon-greedy with 10% explore)
  → embed mutates DOM in-place (no flash, no re-render)
  → behavior captured (147 metrics) → /api/cro9/event
  → outcome (lead/click/scroll-depth) updates MAB weights
```

### Variant generation (Groq)

New variants are generated by Groq (Llama 3.3 70B) from a **base page** +
**winning patterns** + **brand voice profile**. Never Anthropic / OpenAI in
production paths.

```ts
// lib/cro9/variant-generator.ts
import Groq from "groq-sdk";
const groq = new Groq({ apiKey: process.env.GROQ_API_KEY });

await groq.chat.completions.create({
  model: "llama-3.3-70b-versatile",
  messages: [
    { role: "system", content: brandVoiceProfile },
    { role: "user", content: variantPrompt },
  ],
});
```

### MAB allocation

Epsilon-greedy with `epsilon=0.10` (10% explore, 90% exploit). Reward signal
is conversion-weighted: `lead = 1.0`, `email_capture = 0.4`,
`scroll_to_pricing = 0.1`.

State lives in Supabase: `cro9_variants`, `cro9_allocations`, `cro9_events`.

## CRO9 Engine

15KB embed, dropped into every site environment via `<script>` tag or
WordPress plugin (`0nWP v1.1.1`). Captures **147 behavioral metrics**
including:

- Mouse trail entropy, scroll velocity, hesitation points
- Form-field abandonment depth, field re-edit count
- Tab-switch frequency, idle bursts, rage-click clusters
- Viewport mutation correlation (which mutations made them stay)
- Exit-intent vector + dwell-after-intent
- Cross-session identity stitching (CRO9 visitor hash)

All events flow to `/api/cro9/event` → Supabase `cro9_events` →
materialized view `cro9_visitor_journeys`.

## Rollout Playbook — Adding SXO + CRO9 to Any New Domain

### Phase 0 — Inventory (10 min)

1. Run `/api/sxo-audit?url=<domain>` → captures baseline (0–19 score)
2. Capture: hosting, DNS, GA4, GTM, CRM presence, chat widget, consent banner
3. Save to `audits/<domain>.md` (template in `0n-dispatch/templates/audit.md`)

### Phase 1 — Plumbing (30 min)

1. Cloudflare or Vercel → ensure SSL, HTTP/2, Brotli
2. GA4 + GTM container
3. Universal env vars (CRO9 standard, see Reference Architecture)
4. Consent Mode v2 (cookieless ping when no consent)
5. CRM routing → location `AeY8M0GNOuJPNkLQ7AAC` for family sites

### Phase 2 — SXO retrofit (1–3 hrs per page)

Per page:
1. Add BLUF
2. Add `cro9:living` meta + variant pool name
3. Insert table trap above the fold
4. Write 5–7 voice-search FAQs + emit `FAQPage` schema
5. Emit `HowTo` schema where applicable
6. Add 3–5 internal-link cluster
7. Re-run `/api/sxo-score` → must hit ≥ 95

### Phase 3 — CRO9 embed (5 min)

```html
<script async src="https://cro9.com/embed.js" data-site="<SITE_ID>"></script>
```

Add to `app/layout.tsx` (Next) or `<head>` (WordPress via 0nWP plugin).

### Phase 4 — Variant pool seeding (30 min)

1. Identify the 3 highest-traffic pages
2. Generate 3 variants per page via `lib/cro9/variant-generator.ts`
3. Insert into `cro9_variants` table
4. MAB starts cold-start exploration (uniform allocation, 200-visitor warmup)

### Phase 5 — SerpAPI rank tracking (10 min)

1. Add 6–10 target keywords to `serpapi_keywords` (domain-scoped)
2. Daily cron `0 6 * * *` runs `/api/cron/rank-track`
3. Results surface at `/api/dispatch/rank?domain=<domain>`

## Hard Rules (mirrored from `/api/dispatch/rules`)

1. **Groq for all production AI** — never Anthropic SDK / OpenAI SDK in
   prod paths. Local dev / one-off scripts can use whatever; production
   variant generation, chat, scoring, classification = Groq.
2. **No emoji as icons** — Lucide React only.
3. **No inline `style={{}}`** — Tailwind only.
4. **No CSS layering on shadcn** — set CSS vars at `:root`.
5. **Push to `main`** — no branches, no PRs.
6. **PIT tokens MUST be `type:plain` on Vercel** — encrypted = double-wrapped
   = breaks CRM auth.
7. **NEVER say GHL / Go High Level / HighLevel** — always "CRM" or "ROCKET".
8. **Server pages: `getSession`, not `getUser`** — `getUser` is a network
   call that races middleware's cookie refresh and creates auth redirect
   loops. Trust middleware.
